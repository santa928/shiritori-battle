# しりとり辞書の土台

Issue #2（辞書の実現性）の調査と、再現できるオフライン生成処理です。**辞書は人手確認済みの完全な採用語リストではありません。** 日本語の語義を実際に持つソースで生成まで確認しました。原資料の全文アーカイブは同梱していません。辞書確認UI用の選別済み配布物はpublish/site.zip.part001以降の分割ZIPに固定版として保存します。


## ふたり対戦

1台を交互に使い、かな盤を押して入力します。文字は「ひとりずつ」か「ふたりで共有」、制限時間は1手30秒・1分・2分・3分（初期30秒）です。先頭は消費せず、2文字目以降の基底かなは厳密に1回だけ使えます。「もも」は可、「たまたま」は不可。濁音・半濁音・小書きは清音／大書きの文字を使い、長音符は無料です。末尾の長音符は飛ばし、直前の文字でつなぎます（コーヒー→ひ、タクシー→し）。複数の長音符も同様です。つなぐ文字は濁音・半濁音を保ち、小書きは大書きにします。「んー」のような末尾は従来どおり入力できません。

同じ読みは再使用できません。辞書適格な「ん」終わり、時間切れ、降参で負けです。辞書の確認待ちは時間を止め、誤答では残り時間をリセットしません。相手文字の確認中は時間が進みます。成功時は最大2語を表示し、勝負後に全語義と出典を確認できます。ページを再読み込みすると試合は終了します。

辞書更新前から開いている対戦は、同梱された旧辞書への再試行で続けられます。この場合は旧辞書の語義・採否と旧画面のルールのままです。追加された語や新しい長音符ルールを使うには、勝負を終えてからページを再読み込みしてください。新しい画面では辞書取得の失敗後に最新の公開版を探して再試行します。エラー時は文字の編集・削除、確認中は「入力に戻る」で復帰でき、入力に戻った時点で残り時間をリセットせず再開します。

```sh
npm ci
npm test
npm run check
```

新しいUIだけを作り直す場合、変更前の検証済み公開物を退避し、固定辞書区画を再利用します。新規の出力先を指定してください。

```sh
node build-web.mjs --reuse-published BASE_SITE BASE_MANIFEST dist/battle-review
python3 package-site.py dist/battle-review
node verify-site.mjs dist/battle-review
```

原資料の再取得・辞書版更新は伴いません。辞書manifest、全256区画、帰属表示のハッシュ一致と、辞書実装の一致を確認してから再利用します。配布allowlistに対戦モジュールも含め、Actionsは`npm ci`後に検証済みの分割ZIPを再構成し、展開した公開ファイルだけを配信します。

公開切り替え時に開いたままの旧画面を救済する場合だけ、検証済みの旧辞書版を明示的に同梱できます。`OLD_MANIFEST`と同じディレクトリーの分割ZIP（従来の`site.zip`も対応）のSHA-256、旧辞書manifestと256区画のハッシュ・サイズ・版・参照先を確認し、辞書ファイルのみをコピーします。旧サイト全体はコピーしません。通常の辞書生成コマンドでも同じオプションを使えます。

```sh
node build-web.mjs --reuse-published BASE_SITE BASE_MANIFEST dist/recovery-web \
  --retain-published OLD_SITE OLD_MANIFEST
python3 package-site.py dist/recovery-web
node verify-site.mjs dist/recovery-web
```

保持する旧版は`--retain-published`を繰り返して最大2版までです。最新1版は常に維持し、採用した旧版を`build-info.json`と`publish/site-manifest.json`の`retainedVersions`に記録します。旧公開物に含まれている過去版は自動で引き継ぎません。次のビルドで改めて明示しなければ削除される、固定上限による互換措置です（時間ベースの期限ではありません）。配布検証でもこの上限、全区画の整合性、公開allowlistを確認し、余分なファイル・シンボリックリンク・不正な辞書参照を拒否します。


## 辞書確認UI

対戦と独立したmobile向け辞書画面です。読みを確定すると、同音候補の全語義・品詞・出典・採否理由を表示します。漢字から読みを推測せず、確認できない読みは「この辞書では確認できません」と表示します。根拠のある読み候補だけを別途「保留」として示します。対戦画面から独立して利用できます。

```sh
npm test
npm run check
npm run build:web -- /path/to/dictionary-build dist/web
npm run preview -- dist/web
python3 package-site.py dist/web /path/to/dictionary-build/dictionary.json
node verify-site.mjs
```

Node.js 22以上。プレビューは127.0.0.1:4173のみ。初期画面では辞書本文を取得せず、検索時にmanifestと必要な1区画を取得します。固定版をSHA-256で256分割し、ブラウザー側でも区画ハッシュ・サイズ・版を検証します。61,817の読みについて元辞書と区画辞書のlookup一致を確認しました。配布物にはraw、例文、画像、元アーカイブを含めません。語義・補足メタデータはCC BY-SA 4.0で、各候補に元記事リンク、画面とATTRIBUTION.txtに帰属・加工・ライセンス表記を保持します。

GitHub PagesはActionsでpublish/site.zip.part001以降を検証・再構成し、ZIPを展開して配信します。各パートは最大8 MiBで、publish/site-manifest.jsonのzipPartsに順序・サイズ・SHA-256、zipSha256にZIP全体のSHA-256を保存します。`node verify-site.mjs --assemble NEW_ARCHIVE_PATH`は全検証に成功した場合のみ、新規の出力先へZIPを再構成します。publish/site-manifest.jsonにソースhash・辞書版・配布物hashを保存し、workflowが不一致や余分な配布ファイルを検出した場合は公開を止めます。ソース変更後は上記buildとpackageを再実行してください。辞書原資料は公開URLが更新されるため、固定SHAと異なるデータで自動再生成しません。

## 方針

辞書に存在することと、対戦で使えることを分けます。動詞・人名も原資料として残し、読み・表記・品詞・語義・出典を保持します。判定側は語義ごとに採否と理由を返します。「同じ読みの動詞があるから名詞も全部不可」にはしません。語義は生成AIで補いません。

- `dictionary.mjs`: 読みの索引と語義候補、変更可能な採用ポリシー
- `import-jawiktionary.mjs`: 日本語版Wiktionaryの抽出形式を変換する保守的なアダプター
- `build.mjs`: ハッシュ照合、全日本語レコードの保存、索引・監査結果の生成
- `*.test.mjs`: Node標準テストと開発用linkedomによるDOMテスト。語義はすべてテスト専用の創作データで、実際の辞書として使いません
- `source.json`: 検証に使用したソースの固定情報

Node.js 22以上。開発用テスト依存は`npm ci`でインストールします。公開サイトの実行時依存はありません。

```sh
npm test
npm run check
node build.mjs /path/to/raw-wiktextract-data.jsonl.gz /path/to/new-output source.json supplement.json
```

[Kaikkiの日本語版rawデータ](https://kaikki.org/jawiktionary/rawdata.html)から別途取得します。配布URLは更新されるため、現在のダウンロードが保存済みSHA256と異なる場合は**停止**します。新しいスナップショットを採用する際は、日付・抽出器・ライセンス・ハッシュ・境界例を再確認してmanifestを更新してください。ハッシュだけを自動で書き換えないでください。

### 出力

- `archive.jsonl`: 全日本語レコードの原文、sourceId、元ファイル行番号、変換結果または保留理由。読みが取れない動詞や名前も削除しない
- `dictionary.json`: 読みを確定できたレコードの索引用データ。非採用語義も含む
- `report.json`: レコード数・保留理由・仮ポリシーでの候補数
- `source.json` / `ATTRIBUTION.txt`: 出典・ハッシュ・加工・ライセンス情報

出力先が既に存在する場合は上書きしません。原文アーカイブは開発用です。例文・引用・メディア等の追加条件を未監査のまま、そのまま配布・画面表示しないでください。

## 複数読み・補足データ（2026-10-05 UTC）

- `forms` に複数の単独 `transliteration` がある場合、各語義の先頭のかな読み（「、」区切りも可）を照合し、語義ごとに `sense.readings` を保存します。下位語義の明示読みが親と矛盾する場合、本文がない場合、読みの根拠がない場合は空配列で保留します。entry全体の読みと全語義を総当たりで結び付けません
- `lookup` は検索読みと対応する語義だけ返します。例えば日本の国名は「にほん」「にっぽん」の双方に対応しますが、数学用語の日本へ「にっぽん」を追加しません。和文通話表の語義は国名扱いにしません
- `supplement.json` は語義本文を置換しない補足メタデータです。元スナップショットSHA256・行番号・元レコード全体のSHA256・表記・品詞・語義IDに固定し、出典URL・参照日・確認範囲と判断根拠を記録しています。富士山・琵琶湖の読み、東京・日本の特定の地名語義を補います
- 誤採用確認で見つかった略称・作品の巻名・伝説上の固有名等には、同じ仕組みで除外ラベルを語義単位に追加します。通常の名詞の兄弟語義まで除外しません。原資料の分類漏れを全面的に修正するものではありません
- 元レコードが変わった、補足の行が無い、語義IDが重複/範囲外、読みや出典が不正なら生成を停止します。補足の取り込みはCLIの第4引数で明示します。省略時は自動複数読みだけを使います
- 補足データはCC BY-SA 4.0。画面表示時も元記事とライセンス、加工の表示を保ちます。補足データのコピーと内容SHA256を生成物に保存します。参照したページは現在版であり、rawと同一版とは主張しません

`archive.jsonl` は全150,505日本語レコードの原文を変えずに保存します。レコード単位の保留理由と、部分的に読み未確定の語義は別物です。後者は `sense.readings: []` / `unresolved-reading`、集計は `report.unresolvedSenses` です。

公開検索の `not-found` は「この辞書の索引では確認できない」であり、語が存在しないことの証明ではありません。かな入力しかない場合、読み自体が欠落したrawレコードとの対応を推測しません。保留と未収録を分ける監査結果は開発用に残しますが、raw全文をそのまま公開するためのライセンス監査は未完了です。

## 入出力の契約

```js
import {createDictionary} from './dictionary.mjs';
const dictionary = createDictionary(dataset);
const result = dictionary.lookup('コウチャ');
// status: invalid-reading | not-found | candidates
// candidates[]: entryId, senseId, spellings, readings, definitions,
//               pos, labels, readingEvidence, classificationEvidence,
//               source, sourceUrl, eligible, reasons
```

各語義の日本語説明を `definitions[{language:'ja', text}]` に保持します。`sourceId` はmanifestを参照し、`sourceUrl` は元記事を指します。品詞や原文のタグを失わず、辞書更新時に読み直せるようにします。抽出に永続的な語義IDがないため、entryIdはスナップショット＋行番号、senseIdは語義の位置です。**更新を跨ぐ同一語義判定には使えません。**

採用ポリシーは普通名詞と、根拠が明示された地名（行政地名・山川湖など）を許可します。人名・作品キャラクター名・動詞・形容詞・未分類の固有名詞・活用形・略語・数・未解決の参照・造語成分等は不採用です。元品詞は変えず、`name` は検索用に `proper-noun` と正規化し、原文の品詞・カテゴリ・タグはアーカイブに保持します。

地名の例外は `proper-noun` のみで、`place` があっても人名等の除外根拠が優先します。地名はソースの明示タグ・固定のカテゴリ名から分類し、`classificationEvidence` に元の値とentry/senseの範囲を残します。記事単位の地名根拠は1語義の項目のみ採用し、複数語義では語義単位の根拠を要求します。普通名詞のカテゴリは話題名の場合があるため、たとえば「職業姓」に「姓」カテゴリがあっても人名に変えません。名詞と「固有名詞」カテゴリの矛盾は従来どおり `classification-conflict` で保留します。`allowPlaces:false` で地名例外を無効にできます。

`eligible` は辞書ポリシー上の候補であり、末尾「ん」等も含め合法な手の最終判定ではありません。

```js
dictionary.lookup('...', {allowedPos:['noun','verb']});
// 原文や辞書全体を作り直さず、実験用ルールを変更できる
```

小書き・濁点・半濁点・長音は消さず、Unicode幅とカタカナ/ひらがなだけを検索用に正規化します。漢字から読みを推測せず、複数の読みと複数の語義を総当たりで結び付けません。

基本はかな見出し、またはタグが `transliteration` 単独の唯一の読みを採用します。先行対応は、これらが無い場合に限り、全語義の先頭に同一のかな読みが括弧で明示され、元の `forms` の読みもそれを裏付ける場合だけ回復するものです。下位語義に別の読みが明示されれば保留します。括弧だけで本文がないものも回復しません。`readingEvidence.method` で抽出方法を記録します。漢字一般の音訓だけ、本文からの推測、音声ファイル名、他項目からの無条件転用は採用しません。

## 候補ソースと採用理由

1. **日本語版Wiktionary / Kaikki rawを第一候補**。読み・品詞・日本語の語義が取得でき、実データの変換を確認。英語版からの `/dictionary/Japanese` は英語語義なので代用しない。抽出の誤分類・収録偏り・読み欠落・記事単位の版ID欠落がある。rawは複数言語を含むので `lang_code=ja` が必要。
2. **日本語WordNet**。[公式配布](https://bond-lab.github.io/wnja/eng/downloads.html)は日本語語義とsynsetを提供するが、単独では読み・人名区分が足りない。[ライセンス](https://bond-lab.github.io/wnja/license.txt)の著作権表示・免責等を保持する必要がある。語の綴りだけをキーに別辞書の語義へ結合しない。
3. **JMdict / JMnedict**。[EDRDG](https://www.edrdg.org/wiki/Main_Page.html)は読み・品詞・名前分類の補強候補。ただしJMdictの翻訳語義は日本語の国語辞典的説明ではない。[利用条件](https://www.edrdg.org/edrdg/licence.html)と更新要件も確認する。形態素解析用辞書も語義表示の代替にならない。

オフライン同梱は対戦中の速度・再現性に有利ですが、容量・更新・ライセンス同梱が必要。ホスト型は更新や容量管理に有利ですが通信障害・遅延があり、対戦の辞書版本固定が必要です。最初は固定データをオフライン生成し、配布形式は実機サイズ測定後に決めるのが安全です。
