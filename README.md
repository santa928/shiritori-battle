# しりとりバトル

1台のスマホを交互に使う、ふたり対戦と読みから調べる辞書です。公開サイトは静的HTML/CSS/ES Modulesで動き、実行時の外部パッケージはありません。辞書の原資料全文は同梱せず、検証済みの選別済み配布物を `publish/` に保存しています。**辞書は人手確認済みの完全な採用語リストではありません。**

## あそび方

文字は「ひとりずつ」か「ふたりで共有」、制限時間は1手30秒・1分・2分・3分（初期30秒）。先頭は消費せず、2文字目以降の基底かなは厳密に1回だけ使えます。「もも」は可、「たまたま」は不可。濁音・半濁音・小書きは清音／大書きの文字を使い、長音符は無料です。

末尾の長音符を飛ばして直前の文字でつなぎます（コーヒー→ひ、タクシー→し）。連続長音も同様です。つなぐ文字の濁音・半濁音は保ち、小書きは大書きにします。「んー」は入力できません。同じ読みは再使用できず、辞書適格な「ん」終わり・時間切れ・降参で負けです。

辞書の確認中・通信エラー中は時間を止めます。再試行・「入力に戻る」・誤答で残り時間をリセットしません。エラー中に編集すると時間を再開します。相手文字の確認中は時間が進みます。成功時は最大2カード、勝負後は全語義と出典を表示します。再読み込みで試合は終了します。

対戦が終わると辞書タブを開けます。辞書画面では語義・採否理由・出典を確認でき、読みを推定して補いません。「この辞書では確認できません」は語が存在しないことの証明ではありません。

## 開発の入口

Node.js 22.13以降の22系／24以上とPython 3を使います。以下はDocker内で依存を導入・検証する手順です。

```sh
docker compose run --rm dev npm ci
docker compose run --rm dev npm run verify
```

`verify` は整形チェック、lint、全 `.mjs` の構文検査、Node標準テストを順に実行します。整形する場合は `docker compose run --rm dev npm run format`。固定辞書ランタイム・辞書版計算に関わる生成コード、固定対応表・fixtures・JSON・archiveは一括整形対象から外しています。理由と変更時の扱いは [開発・配布手順](docs/release.md) にあります。

原資料がない環境でも、[検証済み公開物の再利用](docs/release.md#元データがない環境での再包装)でUIをビルドできます。`dist/web` を用意したら `docker compose up preview` で `http://127.0.0.1:4173` を開けます。終了はCtrl-C。ソースの `web/` をそのまま配信しません。
